# 五部分表格总览

当前表格依据 MiniC 实现整理；不增加源语言功能。

| 部分 | 文件 | 内容 |
|---|---|---|
| 语法分析 | [文法表](语法分析/语法表格/文法表.xlsx) | 产生式、对应解析函数及源码位置 |
| 语法分析 | [FIRST与FOLLOW表](语法分析/语法表格/FIRST与FOLLOW表.xlsx) | FIRST与FOLLOW |
| 语法分析 | [SELECT集表](语法分析/语法表格/SELECT集表.xlsx) | SELECT集 |
| 语法分析 | [预测分析表](语法分析/语法表格/预测分析表.xlsx) | 预测分析表、冲突与处理、终结符、语法约束 |
| 语义分析 | [语义分析表](语义分析/语义表格/语义分析表.xlsx) | 语义规则、隐式赋值转换、类型与布局、诊断验证示例、示例类型标注、语义诊断索引 |
| 中间代码生成 | [中间代码生成表](中间代码生成/中间代码表格/中间代码生成表.xlsx) | 四元式指令、控制流翻译、示例未折叠四元式、示例已折叠四元式、示例常量池、常量池规则、IR数据结构、优化执行对照 |
| 符号表管理 | [符号表管理表](符号表管理/符号表格/符号表管理表.xlsx) | 符号与作用域规则、公共字段、建表查询接口、示例符号表、符号诊断索引 |

语法集合和 C++ 运行预测表来自同一份 LL(1) 文法；声明形状已写入产生式，预测表没有冲突格。正式解析器使用分析栈查表，匹配后组合 AST；字面量值、赋值左部形状、名字和类型由对应阶段检查。

语义、IR 与符号表共享[表格示例.c](公共示例/表格示例.c)。示例输出为 `16 A ok` 后换行，退出码 0。示例不是空白模板；符号编号、类型标注、常量池和两版四元式均从真实编译器读取，重新生成时会实际编译运行，并核对九种赋值转换与 11 个语义拒绝例子。

设计规则为人工依据源码整理；字段和诊断索引自动提取，实例由驱动读取。来源快照用于提示资料需要更新，不证明规则完全覆盖源码行为。符号实例仅包含驱动公开字段，完整数据结构另列。

## 重新生成与核对

在根目录执行，先构建 workbench_driver。数据与预览放在被忽略的 build 目录；Excel 使用现有外部依赖。

```powershell
python tools/generate_design_tables.py --data build/设计表格 --driver build/ninja/workbench_driver.exe
node tools/export_frontend_tables.mjs build/设计表格/01.json 实验设计/语法分析/语法表格/FIRST与FOLLOW表.xlsx build/设计表格/预览01 <node_modules目录>
node tools/export_frontend_tables.mjs build/设计表格/02.json 实验设计/语法分析/语法表格/SELECT集表.xlsx build/设计表格/预览02 <node_modules目录>
node tools/export_frontend_tables.mjs build/设计表格/03.json 实验设计/语法分析/语法表格/预测分析表.xlsx build/设计表格/预览03 <node_modules目录>
node tools/export_frontend_tables.mjs build/设计表格/04.json 实验设计/语义分析/语义表格/语义分析表.xlsx build/设计表格/预览04 <node_modules目录>
node tools/export_frontend_tables.mjs build/设计表格/05.json 实验设计/中间代码生成/中间代码表格/中间代码生成表.xlsx build/设计表格/预览05 <node_modules目录>
node tools/export_frontend_tables.mjs build/设计表格/06.json 实验设计/符号表管理/符号表格/符号表管理表.xlsx build/设计表格/预览06 <node_modules目录>
python tools/generate_design_tables.py --check --driver build/ninja/workbench_driver.exe
```

核对入口逐单元格检查六份新增 Excel、示例执行和本文的来源快照；不修改现有词法与语法成品。
