## 语言范围与 LL(1) 结论

项目以 C89 为语法参考。当前候选草案包含声明、结构体/联合体、位域、枚举、指针/数组/函数声明符、抽象声明符、函数原型与可变参数、旧式函数定义、初始化、各层表达式及语句构造；这些候选功能不自动成为项目必须实现的范围。预处理属于独立阶段，HASH / HASH_HASH 不进入普通 Token 文法；已有词法规则另保留项目的 `//` 注释扩展。

用户确认 if、else、while、for、do、switch 的控制体使用花括号。项目目标是类似 C89 的自定义 C 类语言，具体文法与语义由项目决定，不以完全遵循 C89 标准为验收目标。当前草案采用块内先声明后语句、for 初始化限表达式，尚未引入 C99 构造；后续可按项目需求调整。

原始候选：117 个非终结符、254 条产生式、20 个冲突格，不能直接作为无冲突 LL(1) 文法。该候选已包含 TYPE_NAME 类型名分类和花括号约束，并非未经上下文处理的标准原始 Token 文法。

上下文 LL(1) 核心：124 个非终结符、267 条产生式；85 个实际输入终结符，加 END_OF_FILE 构成 86 列预测表，SELECT 冲突格为 0。该结论只针对配套 BNF 的上下文终结符流。实现当前草案还必须执行：

- 依据作用域与名字角色按需分类 TYPE_NAME，声明名、成员名及标签名保持 ID；不能预先重分类整个文件。
- 仅在语句入口以 ID 后跟 COLON 分类 LABEL_ID，此适配使用两个 Token，整体不属于原始 Token 流上的纯 LL(1)。
- 赋值左部的 C89 UnaryExpression 形状守卫，以及具名/抽象声明符守卫。
- 后续项目语义检查（C89 作为参考），包括可修改左值、类型组合、旧式函数参数对应关系、常量表达式及控制语句位置。

完整 typedef 作用域适配器、参数声明符守卫及正式 C++ 语法分析器仍属于实现工作。本次交付是文法、集合、预测表和图示设计；验证脚本不能代替正式项目编译器。文件名中保留 C89 字样仅用于保持既有链接，表示参考来源。

## 图形依据与图表对应

参考裘巍《编译器设计之路》第二章印刷页 30 图 2-3 / 图 2-4、页 37 图 2-6，及页 32、38 的转换表与扫描说明。只参考状态圆圈、双圈接受状态、初始箭头、带输入标签的有向边及流程，项目规则仍依据现有状态表。

普通状态 S0-S91 和输入类 C00-C47 与已有 Excel 完全对应。头文件状态 H0-H6 和 C00-C04 独立使用。双圈表示存在接受规则，规则可能输出 Token、跳过内容或报告错误。虚线圈表示其他分图中的目标状态。较长字符集合用 Kxx 缩写，图册第 4 页给出展开。

最长匹配使用最后接受位置，不为模仿书中 Pascal 图添加不存在的“其他字符”边；缺失边对应 -1。EOF 不是输入字节边。
