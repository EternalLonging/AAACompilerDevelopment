# 当前词法表格

[词法状态转换表.xlsx](词法状态转换表.xlsx)直接从当前[词法规则](../../../src/词法分析/词法规则.json)推导，并与 C++ 扫描器使用的 DFA 核对。

| 工作表 | 内容 |
|---|---|
| 状态转换矩阵 | 90 个状态 × 47 类输入；状态、接受规则及下一状态均使用实际数组编号 |
| 状态说明 | 接受态、规则、动作、Token、错误代码及最短到达串 |
| 输入分类 | 47 类互斥字节集合，给出完整十六进制范围和可读字符 |
| 字节映射 | 00–FF 全部 256 种字节对应的类别 |
| 正则规则 | 按优先级排列的 62 条规则及中文说明 |
| 正则定义 | 正则定义及展开结果 |
| 关键字 | 32 个关键字到 Token 种别的精确映射 |
| 固定符号 | 46 种运算符、分隔符及对应规则 |

状态 0 为起始态。转换值 `-1` 表示不能继续，此时扫描器回退至最后接受位置；接受规则 `-1` 表示非接受态。错误和跳过规则也有接受态。最长匹配优先，同长时编号较小的规则优先。

表中状态编号对应 `lexer_dfa.hpp` 的数组下标，与[展示图](../状态转换图/README.md)的 Q 编号分开使用。EOF 由扫描驱动额外追加。关键字先按 ID 识别后查表；保留字和符号被词法识别不表示语法支持全部对应功能。

## 重新生成

在项目根目录执行。数据推导及一致性检查只需要 Python 3.10+；生成 Excel 还需要 Node.js 和 `@oai/artifact-tool`。使用已有依赖目录，工具不会安装依赖或修改源码。

```powershell
python tools/generate_lexer_tables.py --data build/词法表格数据.json
node tools/generate_lexer_tables.mjs build/词法表格数据.json 实验设计/词法分析/词法表格/词法状态转换表.xlsx build/词法表格预览 <node_modules目录>
python tools/generate_lexer_tables.py --check
```

最后一个参数指向含 `@oai/artifact-tool` 的 `node_modules` 目录。预览与中间数据放在被忽略的 build 目录；仓库只保留一份当前 Excel 和生成、核对工具。

`--check` 读取实际导出的 Excel，逐单元格核对转换、输入分类、规则、关键字、符号、来源哈希及工作表结构，同时确认当前 C++ DFA 数据与规则一致。规则更改后未更新表格会导致 `lexer_tables_current` 测试失败。
