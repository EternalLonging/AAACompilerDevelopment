# 语法分析实现

正式入口为 `parse(tokens)`，实现位于 `src/语法分析/parser.cpp`。

解析器采用 **LL(1) 预测分析表、分析栈和语义值栈**。全部语法识别都在 `Parser::run()` 的循环中完成；声明、语句和表达式共用这个循环。

1. 栈底放 EOF，其上放开始符号“程序”。
2. 栈顶是终结符：与当前 Token 匹配，弹出分析栈项，把单词区间压入语义值栈，再推进输入。
3. 栈顶是非终结符：查询 `table[非终结符 - terminal_count][TokenType]`，取得产生式编号。
4. 弹出该非终结符，记下语义值栈的当前位置，把完成标记和产生式右部逆序压入分析栈。空产生式只压完成标记。
5. 右部全部匹配后，完成标记调用 `reduce()`，把右部的几个语义值组合为一个结果，弹出旧值、压入新值。空产生式压入一个空结果。

`reduce()` 是预测分析过程中的 AST 完成动作，不是 LR 分析表中的归约。`declaration()`、`statement()`、`expression()` 等函数只组合语义值，不推进 Token，也不递归调用自己识别语法。这里没有中间匹配树，也没有文法孩子下标或逐节点回查。

`Frame` 保存待匹配符号、完成标记的产生式编号和语义值起点。`Value` 保存单词区间、AST、类型、待合并列表和一元式标记。例如 `加法式 -> 乘法式 加法续` 完成时，两个右部各留下一个 Value，动作把它们组合成表达式，再用一个 Value 替换这两个值。

声明、参数和运算尾表在 Value 中逆序保存，合并时移动尾表并追加前项，放入 AST 时恢复源码顺序。这样长列表不用在每层复制或移动全部元素。函数、结构体和对象的名字、基础类型由所属完整声明补齐；运算尾表直接保存待接上左操作数的 AST 节点，不另建一棵文法树。

表达式优先级直接写在文法中：赋值、逻辑或、逻辑与、相等、关系、加减、乘除取余、一元、后缀、主式。普通二元尾表从左到右组合，所以减法等运算左结合；赋值右部是完整表达式，所以赋值右结合。例如 `a=b=1+2*3` 的 AST 是 `a=(b=(1+(2*3)))`。括号、调用、下标和成员访问仍遵守公共 AST 孩子顺序。

解析过程只读取词法单词并构造语法树，不维护名字表。类型说明符直接对应 `void`、`char`、`int`、`float` 和带标签的 `struct`；名字绑定、类型检查和隐式转换由语义阶段完成。

| 语法类别 | AST 与类型行为 |
|---|---|
| 类型与声明 | 基础类型、带标签的 struct、变量声明、初始化和函数定义 |
| 声明符 | 标识符、一维数组后缀、普通函数参数列表 |
| 结构体 | StructDef 保存按声明顺序排列的 MemberDecl；成员访问使用点号 |
| 表达式 | 加减乘除取余、比较、逻辑、赋值、括号、调用、下标和成员访问 |
| 控制流 | if/else、while、for、return、break、continue 和空语句 |
| 初始化 | 一个赋值表达式；字符数组可以使用字符串字面量初始化 |

所有控制体使用花括号。同一块先写声明再写语句。`for` 的三个表达式可省略，缺失位置使用 `Empty` 节点。数组长度使用正整数字面量，字符串和字符常量的具体值由语义阶段解码。

预测表空格或终结符失配统一报告 `PARSE_EXPECTED`。非终结符恢复时，跳到本行可用预测项继续，或遇到 FOLLOW 时弹出当前非终结符；终结符恢复时，在分号、闭括号和 EOF 前补缺，否则跳过当前输入。每步都会推进输入或弹栈，最多记录 20 条诊断。第一次错误后停用 AST 动作，继续收集语法错误，最终 `ParseResult.root` 为空。括号嵌套和 AST 高度上限均为 128。输入单词表必须包含一个末尾 `END_OF_FILE`，所有 Token 种别必须有效。

## 预测分析表资料

[语法表格](../../实验设计/语法分析/语法表格/README.md)给出实际运行文法的 FIRST、FOLLOW、SELECT 集和预测分析表。唯一文法在 `tools/generate_parser_tables.py` 的 `GRAMMAR`；该工具同时生成 `include/minic/detail/predictive_table.hpp`。运行表包含产生式右部、预测矩阵、FOLLOW 同步集合和符号名称。无预测项的格子为 -1，非空格保存从 0 开始的产生式下标，对应资料中的 P001、P002 等编号。

文法直接区分函数定义与对象声明，只允许单层数组、具名形参和非空结构体。解析器同步拒绝 void 变量及函数类型形参。文法整理没有改变 AST 节点、孩子顺序或表达式结合性，语义分析继续按原接口工作，不需要重写。

FIRST 表示可开始的终结符，FOLLOW 表示可紧随的终结符，SELECT 决定选用哪条产生式。这些集合由产生式统一计算；同一预测格出现两个候选式时停止生成，不能手工覆盖冲突。

修改文法后先运行 `python tools/generate_parser_tables.py --runtime` 重新生成运行表；修改语言构造时同步相应 AST 完成动作，然后按表格目录说明更新资料并运行测试。`--check` 会逐字检查运行表是否来自当前文法，也会核对工作簿；不能只改 Excel。`frontend_test` 检查优先级、结合性、孩子顺序、错误恢复及长列表，`test_parser_tables.py` 另用独立 Earley 识别器对照实际解析结果。

源码只支持直接函数定义和调用。`printf`、`scanf` 是内建教学函数，格式串只使用项目实现的基本格式。语言范围和 AST 合同分别见[语言支持范围](../公共约定/语言支持范围.md)与[数据结构与 AST 约定](../公共约定/数据结构与AST约定.md)。
