# LR 语法分析实现

正式入口仍为 `parse(tokens)`，实现位于 `src/语法分析/parser.cpp`。本实验使用规范 LR(1) 项目集生成 ACTION/GOTO 表。

## 分析栈

解析器维护状态栈和语义值栈。状态栈初始为 `[0]`，语义值栈保存已移进单词的源码范围及已归约的 AST 结果。

每一步读取 `ACTION[栈顶状态, 当前 Token]`：

- 正数表示移进目标状态加一；把当前 Token 的语义值和目标状态压栈。
- 负数表示归约产生式下标加一；按产生式右部长度弹出状态和值，调用 AST 归约动作。
- `32767` 表示接受，`0` 表示语法错误。

归约出左部非终结符后，读取 `GOTO[新栈顶状态, 左部非终结符]` 并压入目标状态及归约结果。

## AST 归约

解析器不建立完整的文法推导树。每次归约直接组合语义值并构造 AST 节点。

加减、乘除、比较和逻辑运算使用左递归产生式。例如：

```text
乘法式 -> 乘法式 "/" 一元式
乘法式 -> 一元式
```

归约第一条时，右部语义值依次是已有的左侧 AST、运算符、右侧一元式。动作直接生成二元节点，左右孩子分别取已有 AST 和新操作数。因此 `12 / 3 / 2` 的归约结果是 `(12 / 3) / 2`，AST 接口与后续语义分析都不变。

赋值采用 `表达式 -> 逻辑或式 "=" 表达式`，所以 `a=b=c` 仍构造成 `a=(b=c)`。调用、下标和成员访问也使用左递归产生式直接归约，不再收集后缀列表。优先级由表达式分层规则决定。

## 表生成

`tools/generate_lr_tables.py` 从规范 LR(1) 项目集生成运行表和 `实验设计/语法分析/语法表格/LR文法.bnf`。相同状态和输入符号若出现不同动作，生成器报告冲突并停止，不覆盖冲突项。

当前完整文法生成 483 个 LR(1) 状态和 4870 个 ACTION 项。表中移进、归约、接受和错误分别编码为正数、负数、32767 和 0；GOTO 表保存归约后的目标状态。终结符编号由公共 `TokenType` 顺序确定，并由静态断言检查。

## 诊断和测试

遇到错误动作时，解析器从当前状态的 ACTION 行列出可接受的终结符，报告第一条诊断并停止。括号嵌套与 AST 高度仍限制为 128。

测试入口包括 `frontend_test`、`lr_tables_current`、`parser_grammar` 和源码联调。前端测试检查左结合 AST、运算优先级、赋值右结合、语法错误位置及完整编译执行。

LR 实验不使用旧 LL 工作簿的源码行号和哈希快照作为验收项。原表格保留供对照，CTest 改为核对实际 LR 运行表，并单独验证规范 LR(1) 算法、冲突检测以及 LL/LR 文法的接受范围。

示例 `examples/lr_associativity.c` 可以用 `minic run examples/lr_associativity.c` 运行，输出为 `2 4 14`；用 `minic parse` 可以查看左结合与右结合的 AST。
