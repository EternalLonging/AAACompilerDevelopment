# 语义分析实现

`analyzer.cpp` 遍历 AST，按源码顺序登记变量、函数和结构体，建立作用域并绑定符号编号。它检查未声明名字、重复声明、左值、初始化、函数实参、返回值、循环中的 break/continue，以及数组和成员访问。

输入契约是当前解析器成功生成、尚未分析过的新 AST。解析器保证根节点、孩子数量、顺序、非空和树高；语义阶段直接使用这些约定，不再逐节点调用 `shape` 或兼容损坏的手工树。

语义实现只处理当前文法开放的构造，删除了前向声明、逗号表达式、位运算、自增自减及源码 const 声明的兼容分支。函数类型从形参节点解析一次建立，不再重复解析并对比同一份签名。普通函数只存在定义，使用时查表即可，不再额外收集调用并在末尾检查定义。

`valid_expression` 和错误类型传播仍然保留：语法正确的源码也可能名字未声明或类型不兼容，这些不是 AST 结构错误。数组地址、隐式转换和结构体布局也仍用于正常编译。

`type_rules.cpp` 实现 `same_type`、`arithmetic_result` 和 `can_assign`。这些公共辅助接口保留内部类型兼容行为；源语言的支持范围由解析器和语义入口共同限制，不能根据 TypeKind 的枚举推断源码支持范围。

`type_arena.cpp` 保存本次编译创建的类型对象；`TypeArenaScope` 指定创建范围。`CompilationResult` 持有类型管理器，AST、符号表和 IR 中的类型指针不能比它活得更久。

语义阶段填写类型和符号，并在必要位置插入隐式转换。数组传参及 scanf 输入采用内部地址。任一 Error/Fatal 阻止后续 IR 生成。
