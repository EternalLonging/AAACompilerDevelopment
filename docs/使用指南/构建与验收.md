# 构建与验收

需要 C++17 编译器、CMake、Ninja 和 Python 3.10+。从项目根目录执行；Windows 中文目录使用 Ninja。

```powershell
cmake -S . -B build/ninja -G Ninja -DCMAKE_BUILD_TYPE=Debug -DCMAKE_CXX_FLAGS=-Werror
cmake --build build/ninja
ctest --test-dir build/ninja --output-on-failure
```

`-Werror` 用于 GCC/Clang；MSVC 严格构建改用 `-DCMAKE_CXX_FLAGS=/WX`。MinGW 构建会在 build/ninja/native_sources 自动复制用于编译的英文路径源码，避免汇编器的中文目标路径限制；修改仍以 src 中的正式源码为准，副本随构建自动更新。

首次配置也可通过 `-DCMAKE_CXX_COMPILER=编译器路径` 和 `-DCMAKE_MAKE_PROGRAM=Ninja路径` 指定工具。

## 当前验收入口

| 部分 | CTest 与覆盖 |
|---|---|
| 词法分析 | lexer_patterns、lexer_dfa_current、lexer_tables_current、lexer_differential：规则接受范围、生成表和 Excel 一致性、与独立逐规则正则对照 |
| 语法分析 | frontend、parser_tables_current、parser_grammar：AST 顺序与恢复、资料一致性、集合边界、真实语法样例的独立文法覆盖 |
| 语义分析 | type_arena、arena_lifetime、m1_pipeline 至 m4_pipeline：类型对象归属、类型和声明检查 |
| 中间代码生成 | constant_pool、m1_pipeline 至 m4_pipeline、workbench：四元式、常量池、执行与优化对比 |
| 符号表管理 | symbol_table：作用域、遮蔽、记录成员、内建函数与重复声明 |
| 五部分设计表 | design_tables_current：六份 Excel 逐格一致性、真实类型转换、诊断例子及两版四元式执行对照 |
| 整体联调 | compiler_flow、source_integration、cli_acceptance、showcase、workbench_service：阶段顺序、源码、命令行、演示和服务 |

安装 Python 时共 22 项 CTest。`source_integration` 按 [manifest.json](../../tests/integration/manifest.json) 检查当前语言范围内的源码：正常程序核对输出和返回值，错误程序核对最早拒绝阶段。

也可执行 `tools/test_backend.ps1 -Compiler 编译器路径`，严格编译并验证独立模块及真实前端。浏览器编辑操作单独使用 `tools/test_workbench_browser.py`，需要额外安装 Playwright；本次目录整理不变更网页交互。
