# GitHub Pages 在线工作台

网站地址：<https://eternallonging.github.io/AAACompilerDevelopment/>。

在线版保留编辑器、Token、AST、符号表、四元式、优化对比、输入输出和文件导入导出。编译器通过 Emscripten 编译成 WebAssembly，在浏览器的 Web Worker 中运行。源码和程序输入保存在浏览器内存中，不提交给编译服务器；刷新前需要自行保存文件或项目。

网站还提供[语法归约动画](https://eternallonging.github.io/AAACompilerDevelopment/learning/reduce-actions.html)。支持的语言范围与本地版相同，以[语言支持范围](../公共约定/语言支持范围.md)为准。

## 自动发布

仓库 Settings → Pages 的 Source 使用 **GitHub Actions**。`.github/workflows/pages.yml` 在合并请求中检查构建和测试，向 `main` 推送后自动发布。也可以在 Actions 的 **Build and deploy compiler website** 中手动运行。

发布顺序为：原生 C++ 严格构建和全部 CTest → WebAssembly 构建 → 静态网站打包 → 浏览器与原生结果对照、网页交互测试 → Pages 部署。测试失败不会发布。编译产物只通过 Actions artifact 交付，不提交到 Git。

部署状态及网站地址可在仓库的 Actions 和 Settings → Pages 查看。以后修改编译器、网页或示例，按功能分支、合并请求、合入 `main` 的流程即可自动更新网站。

## 本地构建网站

安装并激活 Emscripten SDK **4.0.20**，同时准备 CMake、Ninja 和 Python。在已加载 Emscripten 环境的终端执行：

```sh
emcmake cmake -S . -B build/wasm -G Ninja -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF
cmake --build build/wasm --target workbench_driver --parallel 2
python tools/build_pages.py
python -m http.server 8080 --bind 127.0.0.1 --directory build/site
```

浏览器访问 `http://127.0.0.1:8080/`。不要直接双击生成的 HTML；浏览器需要通过 HTTP 加载模块、Worker 和 Wasm。网站资源使用相对路径，可部署到 GitHub 项目网站的子目录。

浏览器测试需要原生工作台程序和 Playwright：

```sh
python -m pip install playwright==1.65.2
python -m playwright install chromium
python tools/test_pages.py --site build/site --driver build/ninja/workbench_driver
```

Windows 的原生程序路径加 `.exe`。已安装 Chrome 或 Edge 时，可通过 `--browser` 指定程序的完整路径。测试会在 `/AAACompilerDevelopment/` 子路径提供网站，比较已有示例及联调用例的完整 JSON 结果，再验证编辑、导出和手机布局。`--url` 可直接检查已部署网站。

## 浏览器运行限制

首次打开需要下载编译器，加载期间会显示状态。每个源文件最多 256 KiB，输入最多 64 KiB，项目最多 33 个文件；执行最多 100,000 条指令、128 层调用。Wasm 线性内存上限为 256 MiB，每个编译运行请求超过 15 秒会终止后台线程，下次请求重新创建编译器。页面编辑不会被后台执行阻塞。

本地 Python 工作台继续使用原有启动方式和 API。网站构建只选择在线运行入口，不改变词法、语法公共接口及 AST 孩子顺序。
