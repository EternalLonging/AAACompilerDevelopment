# 图形工作台

本地网页界面已接入实际 C++ 编译器，提供源码编辑与补全、各阶段图形展示、常量折叠前后对比。服务器只监听本机，不上传源码，运行不需要 npm、在线字体或第三方 Python 包。

## 启动

需要 Python 3.10+，先构建包含 `workbench_driver` 的工程：

```powershell
cmake -S . -B build/cmake -DCMAKE_CXX_FLAGS=-Werror
cmake --build build/cmake
python tools/workbench_server.py --open
```

也可双击项目根目录 `start-workbench.cmd`。启动后浏览器打开 `http://127.0.0.1:8765`；关闭终端或按 Ctrl+C 停止。端口已占用时，改用 `python tools/workbench_server.py --port 8766 --open`。构建目录不同可加 `--driver build/frontend/workbench_driver.exe`。

## 编辑器与补全

默认编辑 main.c，选择右上角示例即可载入现有演示。程序输入框供 scanf 读取；无需在浏览器外的终端输入。Ctrl+N 新建文件；Ctrl+S 保存当前文件到电脑；Tab 输入四个空格；Ctrl+Enter 编译并运行；Ctrl+Space 请求补全。输入名字的两个字符或成员的 `.`/`->` 时也会自动请求补全。

补全候选来自独立 `complete` 接口：先直接词法、语法和语义分析当前编辑的 .c 文件，再按作用域及光标位置查名字；过滤已退出作用域和光标后的声明。未完成的表达式可通过截取光标前片段、补分号和闭合括号恢复已登记符号。界面会说明是否使用了恢复结果，恢复不代表正式源码可编译。记录变量和指针支持直接 `item.sc`、`ptr->sc` 成员候选。

候选只保留与已输入前缀匹配的名字；名字与输入完全相同时排最前，其余符号按当前作用域、外层作用域、全局作用域排序，同一层按名字排序，关键字放在符号后。内层同名符号继续遮蔽外层。输入 `pr` 不会出现 `a`、`main` 等无关名字，没有其他 pr 前缀符号时只显示 `printf`。

候选显示名字、种类和类型。方向键选择，Tab/Enter 或点击插入，Esc 关闭；只替换光标前的前缀，例如 `pr` 变为 `printf`，不能追加为 `prprintf`。左右移动光标或改变选择范围后关闭旧候选；插入前再次核对源码、光标和文件，避免使用过期列表。注释、字符串和字符字面量中不弹出补全。光标按 UTF-8 字节与编译器交互，浏览器内部的 UTF-16 位置会转换后使用。临时源码原样写入 UTF-8，不让 Windows 自动转换换行；界面验证返回的字节范围，再使用编辑器自身的前缀位置替换，避免多行、中文或表情造成错位。

当前补全针对正在编辑的 .c 文件的直接源码，不展开宏或加载头文件中的声明，头文件编辑时不提供语义补全。关键字按编辑上下文筛选，是项目关键字提示，不声称来自完整 LL(1) 预测表；复杂成员链、数组元素成员和不完整声明的恢复仍有范围限制。无法成功恢复时，仍可提供关键字候选，不能把未知名字猜成真实符号。

## 项目与头文件

点击「＋ 新建文件」或按 Ctrl+N，填写 `demo.c`、`src/demo.c`、`config.h` 或 `inc/config.h` 等名字。.c 自动填入最小 main 程序并选为编译文件，.h 初始为空。不覆盖已有文件；重名（包括大小写不同）、项目外路径、保留名字和目录冲突会提示修改。

新建文件保存前，切换文件、打开电脑文件、新建另一文件、选择其他编译文件、载入示例或清空项目都会弹出提示。选「保存到电脑」保存当前内容后继续；选「放弃文件」删除这个新文件后继续；选「取消」或按 Esc 留在当前文件。支持原生保存窗口的浏览器会选择磁盘位置并写入，取消保存不允许继续切换；其他浏览器使用文件下载。点击「保存文件」或 Ctrl+S 也可先保存；「保存项目」保存完整项目后解除新文件拦截。关闭或刷新含未保存新文件的页面时会请求浏览器确认。

文件下拉框切换编辑；「编译文件」选择要运行的 .c 文件。一次只编译所选源码及其实际包含的头文件，其他 .c 不自动编译或链接。编译文件在子目录时，可以用 `#include "../inc/config.h"` 引用同一项目内文件；包含路径始终受项目根目录约束。没有系统标准库或 `-I` 搜索目录。

「打开文件」接收 `.c`、`.h` 或已保存的项目 JSON，导入源码保留文件名，重名覆盖前会确认。「保存文件」保存当前文件；「保存项目」保存全部文件、编译文件选择和输入，之后可重新打开；也兼容旧项目默认 main.c 的保存格式。保存使用原生保存窗口或浏览器下载；源码文件保留文件名，子目录结构可通过项目 JSON 保存。项目仅保存在当前页面内，不自动覆盖磁盘原文件，刷新页面前请保存项目。

## 图形展示

「分析源码」执行预处理、词法、语法、语义，再分别生成两套 IR，不运行用户程序。「编译并运行」增加两侧解释执行。

| 页签 | 实际展示 |
|---|---|
| 语法树 | 真实 AST 节点和父子连线，带节点类型、名字和语义类型；支持缩放、适应宽度、滚动、点击定位、SVG 导出 |
| 单词表 | 宏展开后的 Token 种别、原文、原始文件和行号 |
| 符号表 | 名字、符号编号、类型、作用域与声明行号 |
| 四元式 | 真实函数指令表和常量池，保留 %s/%t/%c 操作数 |
| 优化对比 | 未折叠与已折叠的 IR、指令数量、运行输出、退出码和实际执行步数 |
| 预处理 | 实际宏与头文件展开源码 |

编译失败时仍可查看已完成阶段，未运行阶段显示提示；诊断可点击跳转文件和行。源码修改后旧结果不能导出或用于定位，需要重新分析。默认预处理模式只保证原始文件和行号，列号为 1，不能将其宣传为宏展开后的精确列号。

## 优化对比

`IRGenerationOptions.constant_folding` 默认 true，原 `generate(program, symbols)` 行为保持不变。关闭后保留表达式运算四元式；开启后使用现有安全常量折叠。两次生成读取同一棵已成功分析的 AST，不重复执行语义分析。

两侧解释器有独立输入流、全局存储和调用帧。输入完全相同；两侧都成功且输出、main 返回值一致时才显示“结果一致”。任何一侧失败时不显示等价结论。对比只说明这次输入的结果一致，不是对任意程序的数学证明；常量折叠也不保证每个程序都减少指令。

默认示例包括 `(2+3)*(4+5)` 和短路副作用，输出为 `value = 45, hits = 0`，实测四元式数 39 → 22，执行步数 28 → 18。无副作用纯常量表达式才折叠，不折叠函数调用、对象读取或赋值；溢出、除零仍由运行器诊断，不隐藏错误。对比导出为文本，其他结果可导出为 JSON。

## 验证和限制

```powershell
ctest --test-dir build/cmake --output-on-failure
# 可选浏览器验收，需要安装 Playwright，并先启动服务
python tools/test_workbench_browser.py --browser 'C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe'
```

工程共 19 项 CTest，workbench 检查补全前缀与作用域排序、未完成输入恢复、直接成员/指针成员、注释抑制、真实优化和输出一致性；workbench_service 含 34 项检查，覆盖 C++ JSON 入口、HTTP、多行 LF/CRLF 与中文表情下的前缀字节范围、自定义中文源码文件名、嵌套头文件、项目内相对包含、文件冲突、失败阶段、运行上限与本地请求约束。浏览器独立检查多行源码真实输入 pr 后用 Enter/Tab/点击替换为 printf、完全匹配与作用域排序、光标移动后旧候选失效，以及 Ctrl+N/Ctrl+S、新文件保存/放弃/取消、编译文件切换、项目保存再打开、保留名字的源码导入、AST 导出、报错定位和桌面/手机布局，无页面脚本异常。

单个源码或头文件最多 256 KiB，输入最多 64 KiB；项目最多 33 个文件（一个编译文件加至多 32 个其他文件）。每侧解释执行最多 100,000 条指令、128 层调用，工作台进程限时 15 秒。最多同时处理两个编译请求。基础编译器仍有对象大小与前端深度等自身限制；本地工作台用于教学演示，没有提供完整 IDE、项目链接、C++、完整 C89/C99 或标准库。
