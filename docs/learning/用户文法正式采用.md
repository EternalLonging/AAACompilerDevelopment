# 用户文法已正式采用

项目的正式解析器现已采用用户推导并整理的 116 条产生式，继续使用 LL(1) 预测分析表。唯一生成来源仍是 `tools/generate_parser_tables.py` 的 GRAMMAR；[整理版](用户文法整理版.bnf)保留相同规则，便于按推导时的名称阅读。

## 代码怎样对应文法

- 程序入口为“程序 -> 外部定义 外部定义序列”；“外部定义序列”递归匹配其余顶层定义，遇到文件结束取 ε。另保留原有“程序 -> ε”的空文件分支。此前合并进“程序”的递归已拆回用户命名，顶层 AST 顺序不变。
- “形参”复用类型、名字和数组信息。外层展开时传入声明节点种类，在函数参数处直接建立 ParamDecl，在成员声明处直接建立 MemberDecl。
- “变量声明后续2”的逗号分支接收完整声明后续，只补变量名，不重复创建变量节点。
- “赋值”只传递可选的右侧表达式。变量声明把它作为初值；完整表达式据此建立 Assign。赋值保持右结合，普通二元运算保持左结合。
- “表达式2”允许空串，服务于空语句、return 和 for 的可选表达式；普通“表达式”仍不允许空串。
- “语句”转交 if、while、for、返回语句和代码块各自完成的 AST；else 后可以接块，也可以接 if。
- 文法保留用户的 if/else/while/for 名字；C++ 枚举分别使用条件语句、否则分支、当型循环、计数循环，避开 C++ 关键字。预测表和文法资料仍显示用户名称。

## 与后续阶段的交接

公共 AST 接口和孩子顺序继续沿用。If 的第三个孩子可以是 Block 或下一个 If，后续阶段原本就按语句遍历；不需要修改语义和 IR 的实现。

按值结构体形参现在能由文法生成，并使用现有后端的结构体复制机制。测试确认：函数内修改结构体成员及其数组成员不影响调用方；结构体数组形参仍按地址传递，可以修改调用方对象。

`&` 的操作数收紧为后缀式：`&a`、`&a[i]`、`&s.x` 可进行语法分析；`&-a` 在语法阶段拒绝。可写入性及取地址用途仍由语义检查。词法分析、语义分析、符号表、IR 和解释器的实现未为这次迁移改写。
