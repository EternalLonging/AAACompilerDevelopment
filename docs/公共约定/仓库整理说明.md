# 仓库整理说明

源码按词法分析、语法分析、语义分析、中间代码生成和符号表管理分目录组织。公共接口位于 `include/minic`，公共支持和总控展示使用独立目录。

词法规则唯一来源是 `src/词法分析/词法规则.json`，生成器输出 `lexer_dfa.hpp`。语法规则唯一来源是 `tools/generate_parser_tables.py` 的 `GRAMMAR`，同时生成 `src/语法分析/predictive_table.hpp` 和 `实验设计/语法分析/语法表格` 下的 BNF、FIRST/FOLLOW、SELECT 与预测格。解析器使用分析栈查运行表，并在匹配完成后构造 AST。

构建产物和生成过程文件放在被忽略的 `build` 目录。正式代码、文档、示例和测试应同步更新，避免保留过时的语言范围说明。

本地原生构建统一使用 `build/ninja`，根目录的 `start-workbench.cmd` 默认使用其中的驱动程序。WebAssembly 构建使用 `build/wasm`，网站输出使用 `build/site`；本地工具链仍需保留，不能当作编译缓存一起删除。

旧构建、验证用源码副本、`.vs` 和 Python 缓存可以清理。源码副本中的旧公共头文件可能干扰编辑器解析；日常编辑使用 `src` 和 `include` 中的正式文件。MinGW 当前构建所需的 `native_sources` 由 CMake 自动维护。

`output` 保存本地学习资料及需要保留的历史原稿，不参与编译，也不提交到仓库。清理过程目录前先保留其中唯一的办公文档；独立 Git 副本中尚未合入的提交先保存为 Git bundle。正式实验表格仍保存在 `实验设计`，不能按生成缓存删除。

本地测试样例包统一使用 `output/测试样例`；需要打包时使用 `MiniC测试样例.zip`，无需长期保留重复压缩包。包内指南的构建路径使用 `build/ninja`，独立修改练习按指南在 `build/practice` 下重新建立副本。
